# Development

`src/` is the source of truth. `packages/codex` and `packages/claude` are generated and must not be edited manually. The build copies skills, hooks, runtime, schemas, templates, legacy evidence and integration provenance, then adds host manifests from `platform/`.

For behavior changes, establish a failing test, implement the behavior and run its relevant checks. Before handoff:

```sh
node --test
node scripts/build.mjs
node scripts/verify.mjs
git diff --check
```

Changes to distribution logic also require a second build and identical generated bytes. Tests compare independently prepared disk layouts with audit results and cover failure recovery, manual content, concurrent writers, scoped context and task approval. Do not count string presence in a skill as runtime verification.

Use ignored `tests/.tmp/` for isolated fixtures and host test evidence. Preserve real user configuration, credentials, hook trust and installed plugins. A blocked host test is not a successful test. Exact validation and limitations belong in `docs/verification.md`.

The repository does not install a repository-owned GitHub Actions workflow. Run release checks locally. Commit, push, release and publication require explicit requests. Upstream DryForge material is pinned, license-preserved and never used to override Hames execution rules.
